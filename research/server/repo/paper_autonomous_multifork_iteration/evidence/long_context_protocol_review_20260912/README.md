Encbank's description of 40,960 as native uses configuration metadata and should not override Qwen's model documentation. [Qwen3-8B model card](https://huggingface.co/Qwen/Qwen3-8B#model-overview).

Current LongEval `remote_package/protocol.py:86` explicitly asserts `len(full)+16 <= 40960`. That assertion is our admission guard; extending it prospectively does not require altering the stored model config. Existing approximately 33K cells should be described as unscaled/default-config, not strictly within the published native 32K range.
3. **Documented validated extension: static YaRN to 131,072.** Qwen documents `max_position_embeddings=131072` and `{rope_type:yarn, factor:4.0, original_max_position_embeddings:32768}` together; 65,536 uses factor 2. Static scaling changes shorter-context behavior too. This would be a separate matched protocol applied before construction to all six methods, including H's short chunk-local Write and packed Read. It cannot be mixed with frozen unscaled rows. It is unnecessary for reproducing Encbank's intended extrapolation regime. [Official Qwen Transformers guide](https://qwen.readthedocs.io/en/latest/inference/transformers.html#enabling-long-context).

HF5.5.4 internally normalizes legacy `rope_scaling` to `rope_parameters`. Its current YaRN implementation honors an explicit factor and only derives a ratio when the factor is absent/None; the Qwen guide's warning about old Transformers 4.52.3 should not be misapplied to the pinned 5.5.4 source. [HF5.5.4 RoPE implementation](https://github.com/huggingface/transformers/blob/v5.5.4/src/transformers/modeling_rope_utils.py), [configuration compatibility](https://github.com/huggingface/transformers/blob/v5.5.4/src/transformers/configuration_utils.py).
